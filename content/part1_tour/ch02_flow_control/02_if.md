# 2.2 if with a short statement

An `if` chooses a branch using a boolean expression. Go does not treat zero, empty
strings, or nil pointers as false: write the comparison you mean.

An optional short statement runs before the condition. This is useful when a value is
needed only to make a decision, such as parsing a quantity or opening a file.

## Read the example

```annotate
code: |
  package main

  import (
      "fmt"
      "strconv"
  )

  func main() {
      if n, err := strconv.Atoi("12"); err != nil {
          fmt.Println("invalid quantity")
      } else if n > 10 {
          fmt.Println("bulk", n)
      } else {
          fmt.Println("regular", n)
      }
  }

  // Output:
  // bulk 12

```

## Scope and early returns

The short statement ends at the semicolon. Its variables disappear after the entire
if/else chain. If later code needs the result, declare it before the `if` instead.
Write `} else {` on the same line: Go inserts semicolons at line endings, so starting
`else` on a new line breaks the intended syntax.

In a function, a guard clause often reads better than deep nesting: check an invalid
input, return its error, then put the successful path below the check. For example,
`if n < 0 { return fmt.Errorf("negative quantity: %d", n) }` makes the boundary explicit.

Be careful with shadowing. An `err := ...` in an inner block creates a new variable
when the declaration rules permit it; it does not necessarily update the outer `err`.
Keep scopes small and return the error at the point where you handle it.
